# Ресерч

## Что WebAssembly ускоряет
Только счёт на процессоре внутри страницы (циклы, разбор, кодеки): обычно 1,2–3× к JIT-JS, без доступа к DOM —
каждый вызов DOM идёт через JS. Сеть, сборку модулей dev-сервером, растеризацию, отдельные процессы браузера не ускоряет.

## Замеры (Helium headless, 1920×1040, dev :4310, карта korbor, 91 экран; скрипты measurements/)

### Открытие визуализатора (load-phases.mjs)
| Прогон | DOMContentLoaded |
|---|---|
| холодный vite (после перезапуска) | 5,6 с — из них 5,2 с сервер собирает модули (пауза между шрифтами 136 мс и первым /@fs 5321 мс) |
| тёплый | 0,55–0,87 с |

### Выбор карты korbor → экраны (load-map.mjs, профиль CPU 30 с)
| Событие | мс от клика |
|---|---|
| map.json (5,15 МБ) получен | 149 |
| ноды на холсте | 860 |
| первый живой холст трансляции | 1143 |

Основной поток за 30 с: **простой 27,97 с (93 %)**, весь JS ~1,4 с, включая:
| Где | мс | WASM поможет? |
|---|---|---|
| (program) — нативная работа движка/рендера | 850 | нет |
| Blob — обёртка кадров трансляции | 220 | нет (нативный вызов) |
| react-dom + jsxDEV (dev-сборка React) | ~290 | нет; прод-сборка убирает dev-накладные |
| stream-client receive/onmessage + ScreenView.draw | ~270 | нет: это вызовы браузера (WebSocket, drawImage) |
| zod разбор карты | 65 | теоретически, но выигрыш ≤ 40 мс |
| dagre раскладка | 42 | теоретически, выигрыш ≤ 30 мс |
| xyflow getDimensions | 32 | нет (чтение DOM) |

### Из прошлых эпох (live-load-cpu, perf-and-settings)
- Тяжесть — в процессах браузера: перерастеризация экранов при зуме, запуск 91 страницы в headless — 53 с, 400–1830 запросов dev-модулей на страницу korbor.
- dev-React съедает ~20 кадров/с на зуме.
