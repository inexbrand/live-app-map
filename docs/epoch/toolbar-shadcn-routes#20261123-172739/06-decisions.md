## Автовход

Задача: экраны под ролью открываются без ручного входа — шлюз сам получает сессии ролей у приложения.

| Решение | Почему | Альтернатива отвергнута |
|---|---|---|
| Новый пакет `packages/dev-auth` (`@live-app-map/dev-auth`): протокол, обработчик на Request/Response, клиент | `plugin-api` — контракт плагинов сканера, вход туда не относится; Request/Response подключается в Elysia, Bun.serve, Hono, Next одной строкой | Расширить `plugin-api` — смешение ответственности |
| Адрес `/api/lam-dev-auth/{roles,session}` | Vite фронтендов korbor проксирует `/api` на API: роли находятся через origin любого экрана карты, без настройки адреса | Переменная с адресом API в визуализаторе — лишний шаг |
| Роль несёт `origin` фронтенда | Один бэкенд обслуживает мини-апп и админку: без origin профиль admin попал бы в экраны мини-аппа | Класть сессию во все origin |
| Сессия = `storage` + Set-Cookie + `expiresAt` | Приложение получает то же, что после своего входа (админке нужны refresh- и CSRF-куки) | Только токен — админка выкидывает на вход через 15 минут |
| Доступ: только loopback, иначе секрет `LAM_DEV_AUTH_SECRET`; в production обработчик молчит, korbor плагин не монтирует; пустой `environment` — ошибка | Выдача токена админа без пароля — опасный маршрут | Всегда секрет — лишний шаг на одной машине |
| korbor: копия `protocol.ts`/`server.ts` в `apps/api/src/modules/dev/lam-dev-auth/` (исключена из oxlint korbor) | Пакет не опубликован; `file:../live-app-map` ломает `bun install --frozen-lockfile` в CI и Docker korbor | Зависимость по пути; публикация в npm — решение пользователя |
| korbor выдаёт сессии существующими функциями: `mintAdminSession` (общая с dogfood), `buildSetCookie`/`buildCsrfCookie` админки, подписанный initData (мини-апп меняет его на токен обычным входом) | Не обходить логику входа | Свой JWT в обход |
| Адрес клиента в korbor — `core/peer-address.ts` (WeakMap запрос → адрес в `Bun.serve`) | Сервер зовёт `app.handle(request)`, у Elysia нет объекта сервера | Верить X-Forwarded-For — подделывается |
| Шлюз: `POST /__lam_sessions/auto {origins}` → профиль на роль, `devAuth` в профиле; годный вход не выдаётся заново; истёкший — перед загрузкой страницы (`ensureFresh`) | Не плодить сессии в базе приложения | Выдавать при каждом открытии |
| Запуск — `useGatewayFrames` при открытии/смене карты; тот же набор origin не спрашивается дважды | Хук уже в корне и знает о шлюзе | Вызов в чужом компоненте |
| Лист «Входы»: метка «автовход», ошибки ролей, приложения без автовхода, «Смотреть как» из профилей; ручной вход — под кнопкой | Ручной путь остаётся запасным | Убрать ручной вход |
