# Решения

1. Рантайм — обычный (не модульный) `<script>` в начале `<head>` из текста функций (toString), как пикер шлюза: выполняется до модулей приложения, не требует fs.allow и сборки для браузера. Страховка от keepNames сборщика — `var __name = f => f`. Проверено: после bun build (tarball) и после бандла конфига Vite 8 (rolldown) текст исполняется.
2. fetch/XHR подменяются сразу, а описание состояния приходит промисом с `/@lam/state`: запросы приложения ждут его, не теряются.
3. Id состояния делится по последнему «/»: id экранов (`miniapp:route:/feed`) и ключи компонентов содержат «/».
4. Файл компонента в дереве — из стека JSX, который создал сам компонент (потомок с `_debugOwner` = компонент); `usedAt` — где его вызвали. Строка в React 19 — null (позиция в коде Vite; перевод по sourcemap есть у пикера — mapFrame).
5. Страница компонента: HTML через `server.transformIndexHtml` (преамбула react-refresh и чужие плагины работают), вход — виртуальный модуль `/@lam/entry.js` с абсолютными `/@fs/` импортами. Обёртка — опция `wrapper`, стили — `styles` (у korbor: providers.tsx#AppProviders и src/index.css). Роутера в AppProviders нет — компонентам с useNavigate нужна своя обёртка (решает проект).
6. Общие функции fiber перенесены из пикера визуализатора в sdk/runtime/fiber.ts; пикер их реэкспортирует.
7. Порт 4421 из задания был занят процессом визуализатора :4310 (он держал 4310–4599, см. 09-bugs); живая проверка korbor — на 5422.
