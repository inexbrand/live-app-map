# Brief

## Цель

Владелец: «архитектура API и вся документация не работают — сделай, чтобы работало и красиво
показывалось, и обязательно показывать docs/epoch». Нужны два новых вида визуализатора —
«API» и «Документация» — и MCP-инструменты к ним.

## Готово когда

- [x] Вид «API» рядом с «Экраны» и «База данных»: сервисы → группы роутов по префиксам; у роута
      метод, путь, описание из комментариев, проверка входа (body/query/params из Elysia `t.`/zod),
      роли и доступ, таблицы чтения/записи, экраны-вызывающие, файл:строка.
- [x] Поиск и фильтры: метод, сервис, таблица, «без описания». Переходы роут ↔ таблица ↔ экран.
- [x] Вид «Документация»: эпохи `docs/epoch/<задача>#<дата>/` с датой и статусом (открытые пункты
      09-bugs — «не готово»), файлы 00…09 и INDEX, `docs/agent-notes`, CLAUDE.md/README; markdown
      с нормальной вёрсткой, скриншоты из `screens/`, ссылки из текста на роуты/таблицы/экраны карты.
- [x] Источник — сканер: новый раздел карты `docs` по `--code-dir`; работает на korbor, vpn-saas и live-app-map.
- [x] MCP: `list_epochs`, `get_epoch`, `search_docs`, `describe_api` (архитектура API).
- [x] Вид обсуждён с design-expert: Medeo, без надзаголовков капсом, без 01/02, без градиентных карточек,
      отступы и радиусы из одного набора.
- [x] Доказательства: Playwright-скриншоты всех видов на korbor и на live-app-map; тесты сканера docs и видов.
- [x] Своя ветка, PR в master, не сливать.
