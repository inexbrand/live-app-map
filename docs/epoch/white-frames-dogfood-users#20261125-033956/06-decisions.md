# Решения

- Сид, а не правка выдачи dev-входа: состояние пользователя — данные, выдача не должна молча менять базу. Сид идемпотентен (ключи, coalesce дат, согласие только на отсутствующую версию), всё пакетами.
- Готовность — у документа (запрос навигации главного фрейма / событие load), а не у вызова goto: страница уходит на новый документ и сама. Кадры до готовности отбрасываются по `metadata.timestamp` — запоздавшие кадры загрузки иначе проходят.
- После готовности — один кадр `Page.captureScreenshot`: screencast шлёт кадры только на изменения.
- Повтор оборванного перехода только для пустой вкладки (`about:blank`) и не больше 2 раз; about:blank не считается готовым экраном.
- Пиксели в тесте — из JPEG (jpeg-js), не через canvas: Helium отдаёт canvas белым (защита от отпечатков).
- sample-ids автовхода — через /api фронтенда с куками: это уже часть протокола dev-входа, бэкенд-адрес не нужен.
