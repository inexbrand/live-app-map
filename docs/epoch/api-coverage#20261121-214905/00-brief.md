# api-coverage — покрытие API экранами и автоописания роутов

## Цель
На korbor-all у роутов мало связей с экранами (29 из 314) и описаний (55 из 314).
1. Связь экран → роут: вызов API относится ко всем экранам, из которых он достижим
   (хуки, сторы, сервисные модули, lazy, табы, админка без компонентов в конфиге).
2. Автоописание роута из кода (обработчик, вход, таблицы, доступ, ответ) с пометкой
   «описание собрано из кода», отдельно от авторского; фильтр «Без описания» — по авторским.
3. Пересобрать карты korbor и vpn-saas, цифры до/после.

## Готово, когда
- [ ] Тесты сканера на фикстуре: табы без элемента, стор-фабрика, диспетчер switch, TanStack-страница и loader, алиасы tsconfig, DI-клиент, чужой стор не прилипает.
- [ ] Автоописание: graph + MCP describe_api/get_route + вид «API» показывают оба вида описаний.
- [ ] Список роутов, которые экранами не вызываются в принципе, с причинами.
- [ ] Карты korbor пересобраны, vpn-saas — локально; цифры до/после в 08.
- [ ] e2e весь прогон зелёный, скриншоты «API» до/после.
- [ ] PR в master слит.

## Вне рамок
- Код korbor и vpn-saas (только чтение).
- Поиск вызовов в мобильном приложении korbor как экранов (в карте нет экранов mobile).
