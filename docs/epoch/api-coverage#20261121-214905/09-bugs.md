## Closed

- Ложная связь экрана вакансии рекрутера с `GET /employer/vacancies/:id` (метод `getVacancy` по имени из чужого клиента) — закрыто правилом «метод по имени только из своей фабрики»; route-samples.test обновлён.
- MCP: вторая `routeLine` перекрыла функцию списка — `list_routes` терял method; переименовано в `apiRouteLine`, server.test зелёный.
- Сторы админки korbor с `fetchWithAuth`-параметром и `api.getRaw` не распознавались — закрыто (тест на фикстуре).
- URL-построители для export.csv — проверено на перескане 40140e8: все три `GET /api/v1/admin/{deals,ledger,vacancies}/export.csv` связаны с экраном (`api.getRaw(ledgerExportPath(…))` и т. п.), ограничение больше не воспроизводится.
- `/api/v1/${surface}/support/…` в mobile — не чиним, обосновано (06-decisions эпохи close-open-bugs): параметр на месте литерального сегмента означает «один из двух роутов», сканер не вычисляет значения типа `ChatSurface`; связь с обоими роутами была бы догадкой. mobile в карте без экранов — на «вызываются экранами» не влияет.
- `POST /api/v1/activity/batch` — не чиним, обосновано там же: путь уходит конфигом (`endpoint`) во внешнюю библиотеку телеметрии, запрос шлёт её код; прослеживать конфиги сторонних пакетов — отдельный класс задач.
