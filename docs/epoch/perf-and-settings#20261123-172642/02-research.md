# Ресерч

## Как устроено сейчас
- Каждый живой экран — iframe через шлюз `<профиль>--<цель>--<ячейка>.localhost:4320` (`lib/gateway/gateway-host.ts`).
- Бюджет: живых 6, на паузе 2 (`packages/iframe-policy/src/index.ts:151`), видимость — IntersectionObserver
  (`flow/page-node/use-node-visibility.ts`) → `setVisible` → `recomputeLive` (`store/app/live-slice.ts`).
- Во время зума iframe прячется под снимок (эпоха live-korbor-e2e).
- Настройки: тема, голос, dogfood-вход — в localStorage. **Масштаб, роль, размер всех экранов, бюджеты — только в памяти**
  (`store/app/live-slice.ts`, `store/app/viewport-slice.ts`); «Размер всех экранов» вдобавок переписывает `document.layout`
  и сбрасывается при каждой загрузке карты (`map-slice.ts` loadDocument).
- Сайт: ни в `korbor-site`, ни в `korbor-all` нет `layout.defaultDeviceViewport` и `page.viewport` → 390×844
  (`lib/viewport.ts` DEFAULT_VIEWPORT; `components/toolbar/map-adaptive.ts`).

## Замеры (measurements/probe.mjs, profile-zoom.mjs; монитор 180 Гц, окно 1600×1000, dev-сервер)

| Карта | Действие | FPS | p99 кадра | Долгие задачи | CPU всех процессов |
|---|---|---|---|---|---|
| site (Chrome) | простой 5 с | 179 | 5.7 мс | 0 | 2.1 с CPU за 5 с (6 iframe по ~0.3 с) |
| site (Chrome) | панорама 1.7 с | 172 | 5.7 мс | 0 | **7.6 с CPU** (GPU 1.7, каждый iframe ~1 с) |
| all | зум 1 с | 92 | **111 мс** | **12 / 819 мс** | 1.6 с |
| all / miniapp | панорама | 180 | 5.7 мс | 0 | 1.5 с |

Выводы:
1. **iframe уже в отдельных процессах** (Target.getTargets: тип iframe, у каждого свой renderer). Гипотеза «все в одном потоке» —
   неверна для Chromium. Перенос в отдельный процесс ничего не даст.
2. **Холст при панораме плавный** (≈180 FPS). Синтетика лаг не воспроизводит — нужен сценарий пользователя.
3. **Зум «Весь Korbor» рвётся**: 12 долгих задач. Профиль: `setVisible → recomputeLive → computeLiveBudget` считает
   `resolveLiveUrl` (разбор URL, шлюз) для **всех** нод при каждом изменении видимости (`iframe-budget.ts:22`),
   плюс перерисовка PageNode с тем же расчётом URL (`PageNode.tsx:84`).
4. **Dev-сборка React**: в профиле jsxDEV, validateProperty, runWithFiberInDEV — dev-режим медленнее прода в разы.
   Визуализатор запускается только как dev-сервер (`bun --bun vite`).
5. **Сайт жжёт CPU даже в простое**: каждый живой iframe сайта ~6% ядра постоянно (анимации страницы), при панораме —
   ~1 ядро на iframe (перерисовка при сдвиге). 6 iframe ≈ 4–5 ядер при движении. Это цена «живых» страниц.
6. GPU: 1920×1080 на iframe × 6 — растеризация в 8 раз больше пикселей, чем 390×844.
