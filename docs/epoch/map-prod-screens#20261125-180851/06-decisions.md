# Решения

## Принято

| Решение | Почему | Альтернатива отвергнута |
|---|---|---|
| B. Сборка с NODE_ENV=development, без сжатия, с картами | замер: бандл с React в режиме разработки 162 запроса / 21,7 с CPU — как прод (159 / 22,4); остаются import.meta.env.DEV-ветки korbor (вход dogfood), имена компонентов и _debugStack для пикера | чистый прод: ломает пикер компонентов, вход dogfood, состояния экранов |
| B. Перезагрузка опросом /@lam/build-id раз в секунду | у экранов одной роли общий origin (A1) — 12 постоянных соединений SSE упёрлись бы в 6 соединений HTTP/1.1 на хост и подвесили загрузку | EventSource |
| B. Страница компонента в сборке — отдельный вход со всеми компонентами из states.ts ленивыми импортами, HTML пишется в generateBundle | preview не умеет собирать модуль на лету, как dev-сервер | per-component HTML-входы (пересборка при каждом новом компоненте) |
| B. Файл компонента в бандле — по sourcemap в странице (общий модуль runtime/sourcemap.ts для пикера и components()); кадры, которые карта ведёт в node_modules, пропускаются | кадр стека в бандле указывает на assets/*.js; React лежит в тех же файлах, что код приложения | preserveModules (вернуло бы сотни запросов), раскладка вендоров по чанкам (хрупко между Vite 6 и 8) |
| B. Сайт — next build + next start за прокси, два каталога сборки по очереди | пока идёт пересборка ~25 с, отвечает прежняя версия (проверено: 0 ответов не 200); память 294 МБ против 1166 МБ у next dev --webpack | пересборка в тот же .next (сайт лежит всю сборку) |
| B. Режим — флаг `bun run dev -- --map` в korbor, обычный dev не тронут | пользователь хочет прод на карте, но HMR при обычной работе остаётся | замена dev по умолчанию |
| A1. Адрес экрана без ячейки ноды (live-url), разбор ячейки в gateway-host оставлен; галерея компонентов (снимки) ячейку сохраняет | ячейка нужна была iframe в одной вкладке (общий sessionStorage); экран трансляции — своя вкладка; общий origin даёт общий кэш (8 страниц админки 28–34 МБ против 270–419 МБ). Цена: экраны одного профиля и приложения делят localStorage | ячейка на ноду |
| A2. Постоянный Helium отдельным процессом, CDP :9341 (9222/9223 заняты Helium пользователя, 9333 — e2e), профиль на порт | два Helium с одним профилем не живут; vite подключается, а не запускает | chromium.launch в vite; launchPersistentContext (умирает с vite) |
| A2. Свои вкладки узнаются по списку на диске (targetId → ключ, адрес, итог шагов), а не по глобалу в странице | глобал теряется, если приложение перезагрузилось, пока vite не было; targetId живёт, пока жива вкладка | window.__lamScreenKey + владелец в странице |
| A2. Невостребованные свои вкладки закрываются через 20 с | первый набор карты неполный | закрытие первым sync |
| A2. Куки и хранилища вкладок теперь на диске и переживают перезапуск | цена дискового кэша; сброс — browser:stop и удаление папки профиля | — |
