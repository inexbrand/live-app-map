# Brief

Запрос (2026-11-25): ускорить загрузку экранов карты в headless-браузере. Ответы пользователя: «всё сделать, 2 а 3 да» и
«пусть у нас будут показаны не bun run dev, а именно продакшен в localhost, и чтобы если что-то исправляется, он перезапускался».

## Цели
- [ ] A1. Экраны одной роли и приложения — общий origin шлюза (без ячейки на ноду): общий HTTP-кэш и кэш кода
- [ ] A2. Один headless Helium живёт отдельно от vite (вариант «а»): профиль на диске, vite подключается по CDP, вкладки переживают перезапуск vite; гасится отдельной командой
- [ ] B. Приложения korbor на карте — собранная сборка (vite build --watch + preview на тех же портах), пересборка и перезагрузка экранов при правке (1–2 с)

## Готово когда
- замер до/после (cache-exp.mjs, перезапуск vite) лучше, чем сейчас
- состояния экранов (/@lam/state), страницы компонентов (/@lam/component), автовход работают в собранной сборке
- тесты затронутых файлов зелёные, коммиты в master

## Вне scope
- свой движок / пересборка Chromium (отвергнуто: 02-research эпохи wasm-load-speed)
