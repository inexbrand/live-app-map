## lead (2026-11-25)

- Раскладка — react-resizable-panels 4 через shadcn `resizable`: горизонтально список | центр | правая панель, центр вертикально схема | данные. Размеры запоминаются (`useDefaultLayout`, localStorage, только после действий пользователя).
- ER-схема — React Flow + dagre (LR), ручки на каждой колонке (`<колонка>:in/out`), связь видна от колонки FK к колонке цели. Подсветка связей выбранной таблицы; выбор из списка подводит камеру (fitView по ноде).
- Исходник объявления — новый эндпоинт `GET /__lam_project/source?file=&line=`: файл только внутри корня проекта, объявление верхнего уровня через разбор TypeScript вместе с JSDoc. В карте только строка начала, конца нет — поэтому разбор на сервере, а не новый формат карты.
- Замечание к таблице — в общий список замечаний (`/api/comments`), в привязке новое необязательное поле `code` (kind 'table', имя, файл, строки), pageId `db:<exportName>`. Переход к такому замечанию открывает вид «База данных» с таблицей. Текст для агента — «Замечание к таблице» с местом объявления.
- Документы, упоминающие таблицу, — из графа документации (рёбра `links` на узел `table:<exportName>`), без нового индекса.

| Решение | Почему | Альтернатива отвергнута |

| `DataGrid` принимает необязательный `client` (по умолчанию тот же origin) и `onDirtyChange(count)` | тесты гоняют сетку против настоящего HTTP-сервера на своём порту; смену таблицы делает родитель — ему нужно знать о правках, чтобы спросить подтверждение (`confirmDiscard` экспортирован) | искать сервер на :4310 в тестах |

## Зона db-api (сервер /__lam_db)

| Решение | Почему | Альтернатива отвергнута |
|---|---|---|
| `database: { urlEnv, envFile? }` в LamProjectConfig; проверка в `packages/cli/src/project/config.ts` — только непустые строки, наличие envFile не проверяется | env-файл часто вне git; отсутствие файла не должно ломать скан, вид БД сам скажет «файла нет» | падать при загрузке конфига |
| Источник адреса: сначала `process.env[urlEnv]`, затем envFile; ничего — `off` с причиной и подсказкой | так договорились с лидом; запасного адреса нет | адрес прямо в config.ts (там был бы пароль) |
| Запись только для хостов localhost/127.0.0.1/::1 (все хосты, если их несколько); иначе 403 до подключения | защита чужой БД | разрешать по флагу |
| Интроспекция одним запросом к pg_catalog (колонки, enum, PK, identity/generated); таблица ищется по имени во всех несистемных схемах; нет — 404, в нескольких — 400 | имена в SQL — только из каталога | information_schema (нет enum и порядка PK одним запросом) |
| Значения параметрами `$n::text::<базовый тип>` (format_type(oid, NULL)) | драйвер postgres.js по типу параметра сериализует сам: jsonb заворачивал в JSON-строку, bool из 'true' делал 'f' — через ::text значение идёт как есть; без модификатора varchar(3) не обрезает молча, а падает | `$n::<тип>` (найден баг живым тестом), `$n` без приведения (UPDATE … FROM VALUES даёт text) |
| ORDER BY с приставкой `t.` | голое имя берёт колонку вывода (`col::text AS col`) — сортировка шла по тексту, 11 раньше 2 (найдено живым тестом) | — |
| Пакет: удаления одним запросом `(pk…) IN (…)`, правки — `UPDATE … FROM (VALUES …)` по запросу на набор колонок set, вставки — по запросу на набор колонок (строки из одних DEFAULT — `INSERT … SELECT FROM generate_series(1, n)`); порядок удаления → правки → вставки | без N+1: число запросов зависит от видов правок, не от числа строк; удаление первым позволяет заменить строку новой с тем же ключом | запрос на строку |
| Число затронутых строк сверяется с ожиданием; не совпало — откат и 409; повтор ключа в пакете — 400 | строку изменили/удалили параллельно | молча применить остальное |
| Коды: 23505/40001/40P01 → 409, прочие ошибки Postgres → 400 с текстом и detail, нет связи → 503; status всегда 200 с state | клиенту сетки нужен текст ошибки | 500 на всё |
| Ленивый пул postgres.js, max 3, адрес сменился — старый пул закрывается; конфиг перечитывается на каждый запрос | правка config.ts/env видна без перезапуска | пул на старте dev-сервера |
