- [closed] Набор 4310–4599. Данные sdk (2026-11-25 ~04:30): PID 20376 с командой `bun --bun vite --port 4310 --host` слушал 4421–4423 на 0.0.0.0 и [::]; в диапазоне 4310–4599 был занят каждый порт подряд (что все они у этого PID, sdk не проверял); через минуту процесс сменился. Это и есть перебор «занят → +1» vite под Bun: в vite 6.4.3 единственное место со сдвигом порта — `httpServer.listen(++port, host)` в httpServerStart (dep-Dm0c1Wj2.js:25122), и оно выполняется только без strictPort. После 30aa8e9 strictPort включён, перебора нет. Почему под Bun перебор не останавливался на первом свободном порту, отдельным скриптом не воспроизведено. «Received 92065» sdk не видел, источник неизвестен; это продолжение того же перебора за 65535.
- [closed] Серия правок vite.config.ts за секунду роняла dev-сервер (нашёл states, чинил install, 2026-11-25). Причина в vite 6.4.3: restartServer делает Object.assign(server, newServer) и копирует newServer._restartPromise = null поверх идущего перезапуска. Правка в это окно запускает второй перезапуск параллельно, он слушает ещё не отпущенный порт → «Port N is already in use» (без strictPort здесь был бы перебор +1). Исправлено очередью перезапусков (src/lib/serial-restart-plugin.ts): следующий ждёт конца текущего, правки во время ожидания сливаются в один перезапуск. Воспроизведение: dev-server-restart.test.ts (5 правок обёртки конфига за 0,6 с) — до правки 2× «Port … is already in use», после — 0.
