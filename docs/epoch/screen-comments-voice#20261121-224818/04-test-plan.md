# План тестов

Unit (bun test, реальные функции):
- comments-store: создание, ответ агента, resolve/reopen, свёртка событий в ветку, фильтры, повтор с тем же id (идемпотентно), битые файлы пропускаются.
- MCP tools через callTool: list_comments → add_change_note → resolve_comment → get_comment.
- middleware /api/comments: POST создаёт, GET фильтрует, 400 на пустой текст, 403 на чужой origin.
- picker: построение селектора и пути DOM (happy-dom нет → чистые функции на «псевдо-элементах»), разбор `_debugStack`, поиск исходника в карте кода.
- голос: чистые функции — ресэмплинг в 16 кГц, выбор устройства WebGPU/WASM, слияние черновика.

e2e (Playwright, свой порт):
- comments.e2e: korbor-miniapp → нода → «Замечание» (C) → наведение на компонент (рамка) → клик → текст → Enter → метка на ноде; MCP list_comments видит; add_change_note + resolve_comment → в панели ответ ИИ и статус «исправлено»; общий список с фильтром → переход к компоненту.
- voice.e2e: Chromium с --use-file-for-fake-audio-capture=<wav с русской речью>; первое нажатие → предложение скачать модель → прогресс → удержание клавиши → черновик → текст в поле содержит ключевые слова → отправка.
- Тест распознавания: тот же воркер распознаёт wav-файл (без микрофона) локальной моделью и выдаёт ожидаемые слова.
