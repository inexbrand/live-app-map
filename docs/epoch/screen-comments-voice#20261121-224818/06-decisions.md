# Решения

## Распознавание речи: Whisper через transformers.js в браузере

- **Почему локально в браузере.** Требование — ничего не отправлять наружу. Модель исполняется во вкладке (Web Worker),
  звук не покидает браузер; dev-сервер только отдаёт файлы модели.
- **Почему Whisper.** Одна многоязычная модель на ru/uz/en, язык задаётся явно. Web Speech API в Chrome распознаёт
  на серверах Google — запрещено условием.
- **Почему transformers.js (onnx-community/whisper-*).** Готовые ONNX-веса с квантованием, WebGPU с запасным WASM, кэш в
  Cache Storage. whisper.cpp через wasm быстрее на CPU, но без WebGPU и с ручной сборкой, а длинного аудио у нас нет: фраза до 30 с.
- **Модели на выбор.** Быстрая — base, 80 МБ, q8: русский и английский хорошо, узбекский слабо. Точная — small, крупнее и заметно точнее на русском.
  Максимальная — large-v3-turbo, q4, нужен WebGPU: лучшая для узбекского. По умолчанию base: первая загрузка за минуту,
  распознавание фразы за 2 с на CPU.
- **Хранение.** Браузерный Cache Storage плюс копия на диске `.lam-models/`: модель не качается заново после очистки кэша
  или в другом браузере. Удаление чистит оба места.
- **Зеркало `LAM_MODELS_MIRROR`.** Команда кладёт модели на общий диск, к HF — только при промахе.
- **e2e «первое использование»** не удаляет модель на сервере: окно видит «на диске 0 байт» через подмену ответа /size,
  файлы идут через сервер как обычно — с диска (`.lam-models`, кэш между прогонами) или с HF в чистом checkout.
- **`@huggingface/transformers` в optimizeDeps.include:** его импортирует только воркер, и без include свежий dev-сервер
  перезагружал страницу при первой записи голоса (e2e в чистом checkout ждал 5 минут пустую страницу).
- **onnxruntime wasm — локально** (`/__lam_models/ort/`), не с jsdelivr.

## Выбор компонента — тот же механизм, что у снимка

Второго механизма снимка нет. Пикер — функция в скрипте шлюза (как остальной inject: `toString()`), включается
сообщением `{lam:'pick'}`. Снимок элемента — существующий TabGrabber и машина snapshot-store; цель сессии
`{kind:'comment', pick:'element'|'region'}` вместо прежней `feedback`. Форма FeedbackPanel удалена: замечание к области
идёт тем же полем.

## Привязка: селектор + путь + текст + рамка + снимок + исходник

Селектор ищется короткий уникальный (id, data-testid, два осмысленных класса, nth-of-type только при одинаковых соседях),
утилитарные классы Tailwind и хэши отброшены. Исходник — React 19 `_debugStack` (у React 19 нет `_debugSource`),
позицию переводит sourcemap прямо в странице; элемент UI-кита поднимается по `_debugOwner` до места вызова в коде
приложения. Путь приводится к корню кода через `codeFileOfNode` — то же правило, что у файлов нод.

## Хранение — только дописываемые события

Двое писателей (визуализатор и агент) — каждое изменение отдельным файлом, ветка — свёртка. Порядок — `seq`, не часы
(см. 09-bugs). Формат: `docs/comments-format.md`.

## Где кнопки

Полный e2e показал: при 1024×700 пустая левая панель и кнопки в панели экрана закрывают ноду и мини-карту.
Поэтому начать замечание — иконка в шапке ноды и клавиша C; «Область» — кнопка в подсказке выбора (и ⌥⇧S);
левая панель появляется, только когда у экрана есть ветки. Общий список — кнопка с числом открытых в шапке (⇧C).
