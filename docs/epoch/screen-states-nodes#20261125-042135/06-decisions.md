# Решения

1. Узел-состояние — настоящий AppMapNode в index (не в store.document): id `<экран>@state:<состояние>`, копия экрана (группа, путь, окно), title «<экран> · <label>», states=[состояние с inject.query.lam_state и inject.role], metadata.lamState. Карта в store.document остаётся как есть — её читают экспорт, сравнение, виды API; холст и бюджет живых читают index.document.
2. Узлом становится только состояние по контракту (есть id). Старые name/inject — чипы на ноде, как раньше.
3. Слияние: states.ts (GET /__lam_project/states, форма `{screens, components}` от тиммейта project) поверх states карты по id/name.
4. lam_state = `<id экрана>/<id состояния>` (рантайм делит по последнему «/»), в search адреса (до # у HashRouter); константа продублирована в lib/state-nodes.ts — визуализатор не зависит от пакета sdk.
5. Раскладка: LayoutBox.anchor — экран и его состояния одной широкой коробкой; ряд не рвётся, dagre/полки работают как прежде.
6. Шаги: один исполнитель lib/stream/state-steps.ts для трансляции и снимка; выполняются один раз на переход карты (stepsPending), кадр готовности — после шагов; сбой шага — «шаг N не выполнен: <шаг> — <причина>», таймаут по-русски; итог шагов — сообщение `{t:'steps'}`, сервер повторяет его новой карте при подключении.
7. stepErrors не сбрасываются при загрузке карты (итог приходит раньше карты).
8. Переключатель «Состояния» — в листе «Настройки» (Switch), по умолчанию включён, localStorage `lam.view.showStates`.
