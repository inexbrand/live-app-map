# Решения

## Принято

| Решение | Почему | Альтернатива отвергнута |
|---|---|---|
| Прямая пакетная вставка в таблицы, а не вызов сервисов apps/api | @korbor/db не может зависеть от apps/api; сервисы пишут по одной записи в своих транзакциях (N+1 на сиде) | импорт hire-service/payment handler из apps/api в пакет db — обратная зависимость |
| Деньги — calcCommissionTiyin / calcNetBountyTiyin / calcTrancheParts из @korbor/domain | те же формулы, что у calcDealMoneySnapshot и payment-succeeded | свои вычисления — расхождение при смене формулы |
| Параметры из platform_config, без строки — PLATFORM_CONFIG_DEFAULTS домена | так же значение видит API; на dev-базе таблица пустая | зашитые 1800/3000/7000 в сиде |
| Стабильные id: sha1(пара пользователей + ключ записи) в формате uuid v5 | повтор попадает в те же строки, ON CONFLICT DO NOTHING; тестовая пара не пересекается с dev-парой | маркер в тексте + поиск перед вставкой — лишние запросы |
| Id уведомления от кода и ключа записи, не от event_key | event_key статуса кандидата содержит момент (`at`), сдвигается с now — первый вариант дал 4 лишние строки на повторе (поймал тест) | id от event_key |
| Уведомления status=delivered | pending забрал бы воркер outbox и пошёл в Telegram с фиктивными tg id | pending |
| Вакансия после найма остаётся hired, в т.ч. при completed-сделке | так делает код: markHired ставит hired, GUARANTEE_STARTED никто не вызывает | статус guarantee/completed у вакансии — состояние, которого прод не создаёт |
| Нет payment_intent у awaiting_payment | intent создаёт маршрут оплаты; активный intent без checkout_url сломал бы экран оплаты | активный intent-заглушка |
| Рекрутер уровня 0 — отклики только на junior | allowedVacancyLevels(0) = junior; take на specialist запрещён доменом | повысить уровень верификации в сиде — чужая зона (онбординг seed:lam-users) |
| Каталог текстов в двух файлах (вакансии/кандидаты и переписка/звонок/отзывы) | файлы до 300 строк | один файл 332 строки |
