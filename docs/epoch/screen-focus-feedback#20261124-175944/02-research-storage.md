# Хранение замечаний: что есть и сколько стоит

## Как устроено сейчас
- Замечания уже хранятся на диске: `.lam-feedback/comments/<id>/` (вне git), каждое изменение — отдельный неизменяемый JSON-файл-событие, снимок — `shot.png`. Код: packages/mcp-server/src/comments-store.ts, схема — comments-schema.ts.
- Агент читает и отвечает по MCP (list_comments, get_comment, add_change_note, resolve_comment, reopen_comment) — packages/mcp-server/src/comment-tools.ts.
- Визуализатор: GET/POST /api/comments (apps/visualizer-spa/src/lib/comments-middleware.ts), опрос каждые 3 с (lib/comments/use-comments.ts, POLL_MS).

## Почему не localStorage и не куки
- localStorage живёт внутри браузера (профиль Helium, origin localhost:4310). Агент — отдельный процесс, прочитать его не может; другой браузер/профиль/порт — замечаний нет; очистка данных сайта — всё пропало. Квота ~5 МБ, снимки туда не влезут.
- Куки: 4 КБ на штуку и уходят с каждым запросом, включая каждый запрос к iframe — хуже всех вариантов.
- MySQL/Postgres: лишний контейнер на 200–500 МБ ОЗУ ради сотен записей; файлы уже дают одного писателя на файл без блокировок.

## Замер (bun, scratchpad/bench-comments.ts, по 3 события на ветку, без снимков)
| веток | listComments, мс | ответ JSON |
|---|---|---|
| 100 | 29–35 | 82 КБ |
| 1000 | 249–567 | 822 КБ |

Опрос раз в 3 с: при 1000 ветках dev-сервер синхронно блокируется на 0,25–0,57 с каждые 3 с (до ~19% одного ядра), браузер разбирает ~16 МБ JSON в минуту. Снимок допускается до 15 МБ PNG (MAX_SNAPSHOT_BYTES).

## Что поменять (предложение)
1. Кэш свёртки в памяти dev-сервера + fs.watch на папку comments: перечитывать только изменённую ветку.
2. Вместо опроса — SSE `/api/comments/stream` (событие «ветка X изменилась»), либо опрос с версией: `?since=<версия>` → 304 без тела.
3. Список отдаёт сводку (id, статус, текст, привязка, число ответов), события — по запросу ветки.
4. Снимок — только область компонента, WebP/JPEG до ~200 КБ, отдельный предел; картинки в панели грузить лениво.
5. Формат на диске оставить (события, один писатель на файл) — MCP агента не меняется.
