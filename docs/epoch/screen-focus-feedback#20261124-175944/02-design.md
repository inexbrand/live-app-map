## Что плохо сейчас

1. **Замечания разнесены по трём местам.** Начать — значок 15 px в шапке ноды или клавиша C; поле — всплывающее окно у компонента; ветки — левая панель, которая появляется только после первого замечания (`ScreenCommentsPanel` возвращает null при `mine.length === 0`); общий список — тоже слева. В правой панели выбранного экрана замечаний нет вообще. Главный путь продукта — «дать правку агенту» — в панели экрана отсутствует.
2. **Правая панель собрана для разработчика, а не для проверки.** Сверху вниз: адрес в textarea на три строки, роли, три кнопки, где главная (белая, залитая) — «В новой вкладке», бейдж «живой», лог, фильтр кода, 18 карточек API. Чтобы дойти до чего-то про качество экрана, листать нечего — этого там нет.
3. **Выбранный экран не в центре и мелкий.** Нода 320 px с окном 390 px — масштаб около 0,5; выбирать компонент курсором на такой картинке трудно. Панель справа перекрывает соседние экраны, камера на выбранный не едет.
4. **Затемнение уже есть, но шумит:** связи между экранами рисуются поверх погашенных экранов и через выбранный, подписи у гашёных нод читаются.
5. **Статусов два (open/fixed), а человеку нужно три:** «ждёт агента», «агент ответил — проверьте», «исправлено». Сейчас ответ агента виден только внутри ветки, на метке и в счётчике его не отличить от нового замечания.
6. **Кнопки ветки равного веса:** «Показать», «Исправлено», «Для агента» — три серых с иконками, ни одна не главная.
7. **Клавиша C не указана в справке** (`ShortcutsHelp.tsx`, массив `SHORTCUTS`): её нет в списке, как и ⇧C.
8. **Бейдж «живой» — самый яркий элемент панели** (белая заливка) при наименьшей важности.

## Что показывать

### В фокусе экрана (холст)

| Приоритет | Что | Как |
|---|---|---|
| 1 | Сам экран крупно | Камера ставит экран в центр видимой области (без ширины панели), масштаб — по высоте окна, до 1:1 |
| 2 | Подсветка компонента под курсором | Синяя рамка 2 px и ярлык с именем компонента React над ней; режим выбора включён сразу |
| 3 | Метки замечаний на экране | Капля у левого верхнего угла компонента, цвет по статусу (ниже) |
| 4 | Под экраном | «‹ предыдущий», переключатель «Выбор компонента C / Работа с приложением I», «следующий ›» |
| — | Остальные экраны | Прозрачность 22 % и ч/б, по ним можно нажать — фокус переходит. Связи скрыты |
| — | Над экраном | Название, путь, «N открыто» цветом внимания |

### Правая панель — по приоритету

1. **Шапка:** название экрана, точка «живой» + путь + размер окна одной строкой; справа иконки «открыть во вкладке», «копировать адрес», «закрыть». Роли — переключатель под названием (если у экрана есть роли).
2. **Вкладки:** «Замечания N» (открыта по умолчанию) · «Код» · «Лог». Код и лог уходят во вкладки — они нужны редко, а сейчас занимают 90 % высоты.
3. **Замечания экрана**, порядок групп: «Проверьте» (агент ответил) → «Ждут агента» → «Исправлено · N» свёрнутым.
4. **Поле замечания** с привязкой: компонент + файл:строка, текст, голос, «Отправить».

**Убрать или спрятать:** textarea адреса (иконка копирования хватает), «Клики в iframe» (переключатель под экраном), кнопку «Для агента» (иконка в ветке, агент и так читает по MCP), бейджи «живой / закреплён» (точка у пути), «Фильтр кода» и карточки API (вкладка «Код»), лог (вкладка «Лог»).

## Сценарий «экран → компонент → сказать → отправлено»

| Шаг | Сейчас | Предлагаю |
|---|---|---|
| Выбрать экран | клик по ноде | клик по ноде: камера в центр, остальные гаснут |
| Включить выбор компонента | клик по значку в шапке ноды или C | не нужно: в фокусе выбор включён |
| Выбрать компонент | клик в экране, ждать снимок | клик в экране |
| Сказать или написать | поле во всплывающем окне | поле в панели (А, В) или у компонента (Б); ⌥ удерживать — голос |
| Отправить | Enter или «Сохранить» | Enter или «Отправить» |
| Где увидеть итог | левая панель, отдельно от правой | там же, где писал, ветка с меткой «Ждёт агента» |
| **Кликов** | **3** + ввод | **2** + ввод; следующий компонент того же экрана — **1** |

Кнопка называется «Отправить», а не «Сохранить»: человек отдаёт задачу агенту, текст кнопки называет действие (buttons-cta, CJq0amJA28l).

## Состояния

| Состояние | Что видно в панели | На экране |
|---|---|---|
| Пусто | «Замечаний к экрану нет» + одна строка, как начать | рамка при наведении |
| Наведение | то же | синяя рамка + имя компонента |
| Черновик | привязка «StatusFilter · файл:строка» с крестиком (снять → замечание к экрану целиком), поле в фокусе | рамка у выбранного остаётся |
| Голос | строка «Слушаю…» с пульсом и живым черновиком | — |
| Отправка | кнопка «Отправляю…» неактивна, ветка с крутилкой | — |
| Отправлено | ветка в группе «Ждут агента», всплывашка «Отправлено агенту», поле пустое | метка-кольцо |
| Агент ответил | ветка в «Проверьте»: ответ, файлы, коммит; «Принять» (главная) и «Не исправлено» | метка залитая, цвет внимания |
| Исправлено | группа «Исправлено · N» свёрнута | маленькая серая метка |
| Ошибка | текст остаётся, под полем «Не сохранилось: сервер замечаний не ответил. Текст на месте.», кнопка «Повторить» | — |
| Пустая отправка | под полем «Напишите, что не так, или скажите голосом (держите ⌥)» | — |

«Не исправлено» открывает поле ответа в ту же ветку — новый текст уходит событием reply, статус → open.

## Метки на экране

- Капля 16 px у левого верхнего угла компонента (как сейчас в `CommentMarkers`), три вида: **кольцо** — ждёт агента, **залитая цветом внимания** — агент ответил, **серая 10 px** — исправлено.
- Наведение на ветку в панели → рамка цветом внимания у компонента на 1,4 с. Нажатие на метку → ветка в панели.
- Без номеров на метках (правило пользователя no-ordinal-numbers).

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| нажатие по экрану | фокус |
| C | выбор компонента (в фокусе включён по умолчанию) |
| I | работа с приложением: нажатия уходят в iframe |
| [ и ] | предыдущий и следующий экран, не выходя из фокуса |
| Enter / ⇧Enter | отправить / новая строка |
| ⌥ удерживать | голос (как сейчас) |
| Esc | снять компонент → выйти из фокуса |
| ⇧C | все замечания проекта (как сейчас) |

C, I, [ ], ⇧C добавить в `SHORTCUTS`.

## Варианты

- **А — лента и поле внизу** (`prototypes/a-feed.html`): одна лента, поле прижато к низу панели.
- **Б — поле у компонента** (`prototypes/b-inline.html`): поле всплывает справа от экрана напротив компонента, панель — только список.
- **В — инспектор компонента** (`prototypes/c-inspector.html`): два уровня панели — экран (группы по компонентам) и компонент (карточка, его замечания, поле).

**Рекомендация — В.** Карточка компонента показывает то же, что получит агент (имя, цепочка, файл:строка), и его прошлые замечания рядом с полем — меньше дублей. Б отбрасываю: возвращает «ввод в одном месте, история в другом», то есть нынешнюю проблему, и окно перекрывает соседний экран.

## Что нужно от данных

- Статус «Проверьте» выводится без смены схемы: последнее событие ветки — от агента (reply или status fixed с author agent), и после него нет события пользователя.
- «Принять» — событие status fixed от user. Отдельного статуса «принято» нет; если агент сам ставит fixed, без события пользователя ветка остаётся в «Проверьте».
- Камера в фокусе должна учитывать ширину панели: центр — по видимой части холста.

## Проверка

- Прототипы открыты в Helium (1600×950): тёмная тема — состояния «Агент ответил», «Черновик», «Много замечаний», «Ошибка», карточка компонента (В); светлая — «Много замечаний» (А) и карточка компонента (В). Снимки в `prototypes/shots/`. JS всех трёх файлов проверен `node --check`.
- Не проверено: узкое окно (меньше 1280), работа с живыми iframe (в прототипе — HTML-заглушки), реальный выбор компонента внутри чужого origin, голос.
- В светлой теме погашенные белые экраны почти сливаются с фоном — для светлой темы гасить затемнением, а не прозрачностью; в прототипе это поправлено только частично (прозрачность 45 %).

## Открытые вопросы к пользователю

1. В фокусе нажатие по экрану сразу выбирает компонент, а чтобы покликать в самом приложении, нужно переключиться (I). Так? Или наоборот — по умолчанию приложение кликабельно, а компонент выбирается с зажатой клавишей (как в инструментах разработчика)? Рекомендую первое: экран сейчас и так не кликабелен без «Клики в iframe».
2. Вариант панели: В (рекомендую), А или смесь (В + поле внизу на уровне экрана)?
3. Нужна ли кнопка «Принять» после ответа агента, или достаточно, что агент сам ставит «исправлено»? Без «Принять» не будет различия «агент ответил» и «я проверил».
4. Вкладки «Код» и «Лог» в панели экрана оставить или убрать совсем — код есть в отдельном виде «API», лог нужен редко?
5. Масштаб в фокусе: по высоте окна (как в прототипе) или 1:1 с прокруткой экрана? Длинные страницы сайта по высоте станут мелкими.
